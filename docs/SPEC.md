# 제때받기 개발 명세 (v2, 2026-10-06)

이 문서는 이전 "개발 마스터 프롬프트"를 최신 방향으로 고친 판이다. 이전 판과 다를 때는 이 문서를 따른다.

## 0. 이전 판에서 바뀐 점

| 항목 | 이전 판 | v2 |
|---|---|---|
| 제품 정의 | 정산검증 Agent 일반 | 정산 문서·입금을 연결해 **차액과 지급 지연**을 확인하고, 근거가 부족하면 **필요 서류를 안내**하며, **공개 의결서로 검산 성능을 평가**하는 Agent |

## 1. 제품 범위

사용자(소규모 납품업체 담당자)는 정산서·공제 내역·세금계산서·입금 내역·약정서를 올리고 다음을 본다.

1. 어떤 거래의 금액이 맞지 않는지(미입금, 부분 입금, 차액)
2. 기준일과 적용 조건이 확인된 거래의 지급기한·지연일수·지연이자(코드 계산)
3. 계산에 필요한 근거가 없을 때 어떤 서류가 필요한지
4. 모든 결과의 원문 위치와 계산 가정
5. 새 입금·정정 문서·추가 약정이 들어왔을 때 영향받은 결과와 기존 확인(승인)의 유효성

첫 버전에서 하지 않는 것: 위법 여부 판정, 법적 권리 확정, 회수 가능성 예측, 보험금 산정, 회생·세금·대출 판단, 외부 청구·독촉·대리, 성공보수.

출력 표현 원칙: "차이 / 필요 서류 / 확인이 필요한 조건 / 관련 근거"로만 표현한다. "위법", "받을 수 있다" 같은 판단어를 쓰지 않는다.

## 2. 현실 제약

- 개발자는 1인이며 기업 인맥·협력사 장부·전문가 라벨링·상시 GPU가 없다.
- 노트북 CPU, 공개 자료만으로 설치·데모·테스트·평가가 돌아가야 한다.
- 기본 설정은 **오프라인 모드, 유료 호출 예산 0원**이다. API 키가 있다는 이유만으로 유료 호출을 하지 않는다.
- 로컬 개발 DB는 SQLite, 운영 DB는 PostgreSQL이다. 두 DB 모두에서 같은 마이그레이션이 동작해야 한다.
- 이 PC에는 Docker가 없다. Docker Compose 파일은 제공하되, 로컬에서 실행하지 못했으면 그렇게 기록한다.

## 4. 법정 지급기한 규칙팩 (첫 규칙)

- `kr.large_retail.art8.direct_purchase` (직매입): 기산일 = 상품수령일(공정위 2026 쿠팡 의결: 납품업자가 상품을 인도한 날, 상품하차일). 기한 = 기산일 + 60일. 시행 2021-10-21.
- `kr.large_retail.art8.consignment` (특약매입·위수탁·임대을): 기산일 = 월 판매마감일. 기한 = 기산일 + 40일.
- 지연이자 = 미지급 원금 × 연 15.5% × 지연일수 / 365 (고시). 원 단위 처리(절사/반올림)는 설정값이며, 결과에 사용한 방식을 남긴다.
- 기한 말일이 토·일·공휴일일 때 다음 영업일로 넘길지는 설정값(`rollover`)이다. 의결서에도 두 방식이 섞여 있으므로, 적용 조건으로 정할 수 없으면 두 계산과 미확인 조건을 함께 보여 준다.
- 개정 규칙(직매입 35일, 월 1회 정산 시 매입마감일+20일, 특약매입 20일)은 `effective_from = null`인 비활성 버전으로 등록한다. 시행일이 정해지면 그 날짜 이후 수령·판매분에만 적용한다.
- 기준일(상품수령일·판매마감일)이 없으면 계산하지 않는다. 세금계산서 작성일로 대체하지 않는다. 필요한 서류(입고·하차 기록, 판매마감 내역)를 안내한다.

## 5. 기능 요구사항 (요약)

아래는 이전 판의 요구사항 중 v2에서도 그대로 유지하는 핵심이다.

- **입력**: CSV/XLSX/텍스트 PDF. 스캔 PDF는 OCR 공급자가 설정되지 않으면 `UNSUPPORTED_SCAN` 상태를 돌려준다. 파일 손상·OCR 실패를 "거래 없음"과 구분한다. 홈택스 세금계산서 엑셀과 국내 은행 거래내역의 대표 열 이름을 인식하고, 모르는 양식은 열 매핑 확인 단계를 거친다. cp949/utf-8-sig 인코딩, 엑셀 일련 날짜, 앞자리 0 거래번호, 음수·취소를 명시적으로 처리한다.
- **원문 위치**: 모든 사실(Fact)은 SourceSpan(문서 버전, 시트·행·열 또는 페이지·문자 범위, 원문 발췌)을 가진다.
- **돈과 시간**: 금액은 정수 최소단위(원) 또는 Decimal. float 금지. 업무 날짜(date)와 시스템 시각(UTC aware)을 분리. 표시 시간대 Asia/Seoul. valid time과 known time 분리, `as_of` 조회 지원.
- **대사**: 거래번호/상대방/기간/금액으로 후보를 좁히고 결정적 제약(배분 합계 보존, 같은 입금 중복 소비 금지, 허용 오차)을 적용한다. 부분·합산·분할·공제·환불·수수료·동액 모호 거래를 지원한다. 조합 탐색은 후보 수·시간 상한을 두고 넘으면 `AMBIGUOUS`. LLM은 후보·설명만 제안하고 최종 수치는 코드가 정한다.
- **상태**: `ReconcileStatus = MATCHED | PARTIAL | UNMATCHED | AMBIGUOUS | CONFLICT | INSUFFICIENT_EVIDENCE`, `ReviewStatus = DRAFT | VERIFIED | APPROVED | REVIEW_REQUIRED | SUPERSEDED`. VERIFIED는 기계적 검사 통과일 뿐 법적 정당성을 뜻하지 않는다.
- **근거·의존성**: 문서→사실→계산→결과 의존성과, "조회 범위·결과 집합·누락 상태"에 대한 의존성을 함께 저장한다. 새 자료가 "근거 없음" 판단을 바꿀 수 있어야 한다.
- **재계산**: 결정적 전체 재계산을 기준으로 두고, 같은 스냅샷에서 선택적 재계산 결과가 전체 재계산과 일치함을 검증한다. 영향 범위가 불확실하거나 의존성이 추적되지 않으면 전체 재계산으로 돌아간다.
- **승인**: 승인은 결과 해시·입력 스냅샷에 묶인다. 확인 API는 기대 결과 해시를 받아 낙관적 동시성 검사를 한다. 관련 근거가 바뀌면 현재 유효 상태를 `REVIEW_REQUIRED`로 바꾸되 과거 승인 기록은 지우지 않는다. 보고서 내보내기도 현재 유효성을 다시 검사한다.
- **멀티테넌시·보안**: 모든 영속 객체에 tenant_id. API·MCP·DB·캐시·다운로드에서 회사 간 접근 차단. 인증은 서버가 결정하고 클라이언트가 보낸 tenant_id를 신뢰하지 않는다. 업로드 크기·MIME·경로 검사, CSV formula injection 방지, 문서 속 지시문을 실행 권한으로 해석하지 않음.
- **LLM·Agent·MCP**: LLMProvider(상용 API + replay/fake). 역할: 문서 판독, 미확인 정보 조사, 검증. 단일 Agent와 역할 분리 구성을 같은 입력·도구·예산으로 실행 가능. API와 MCP는 같은 application service를 호출. 실행별 step·token·시간·비용 상한. 모델 자기평가 숫자를 확률로 표시하지 않음.
- **운영**: API 프로세스와 worker 프로세스(같은 코드베이스, DB 기반 작업 큐), health/readiness, 마이그레이션, 정형 로그, 백업·복구·배포 runbook.

## 6. 평가 (실제 데이터만)

| 평가 | 데이터 | 지표 | 주의 |
|---|---|---|---|
| E1 사건 단위 검산 | 의결서 본문의 합계·범위(예: 지연 1~233일, 지연이자 합계) | 본문 수치와 엔진 계산의 일치(행 데이터가 있을 때) | 본문에 행 데이터가 없으면 계산하지 않음 |
| E2 행 단위 검산 | 의결서 별지 표 이미지에서 전사한 행(출처 flSeq·표 번호·행 번호) | 지연일수 정확 일치율, 지연이자 ±1원 일치율, 방식(rollover/반올림) 분기 | 전사는 "검증 전" 표시. 표의 수치는 피심인 제출 자료를 옮긴 것일 수 있음 |
| E3 기준일 보류 | 의결서 행 중 기준일이 없는 행 | 계산 보류 정확도, 필요 서류 안내 | |
| E4 실제 P2P 흐름 | BPI 2019 | 입고·송장·지급 연결률, 금액 불일치 비율, 지급 소요일 분포, 처리 시간 | 정답 라벨이 없으므로 정확도로 주장하지 않음 |
| E5 약정 조건 추출 | 공정위 표준거래계약서 | 지급기한·기산점 조항 추출 일치 | |
| E6 재계산 동등성 | 위 실제 데이터에 실제 정정 이벤트를 순서대로 적용 | 전체 vs 선택적 재계산 결과 차이 0, 재계산량 | |

실행 기록에는 코드·데이터·규칙 버전과 해시, 설정, 모델·프롬프트 해시, 비용을 남긴다. 결과 파일이 없으면 숫자를 쓰지 않는다.

명세 본문은 바꾸지 않고, 구현이 명세를 구체화한 부분만 적는다. 계약 세부는 `docs/ARCHITECTURE.md`.

- 환경은 `dev`·`test`·`prod` 세 가지만 허용하고, `prod`의 필수 설정(JWT 서명 키, PostgreSQL, https 허용 출처,
  Secure 쿠키, 본인 DRF OC, live LLM 예산·공유 예산 DB)이 없으면 시작하지 않는다(§2 "기본 설정" 구체화).
- 화면 인증은 HttpOnly 쿠키 세션 + CSRF 헤더이며, CLI·MCP는 API 토큰을 쓴다. 테넌트는 서버가 정한다(§5 보안).
- Agent 조사(단일·역할 분담)는 결과 상세 화면 → API → worker로 연결되었다. 기본 `offline`은 LLM을 부르지
  않고, `live`는 서버 설정이 허용할 때만 실행된다. 조사 결과는 엔진 수치를 바꾸지 않는다(§5 LLM·Agent).
- XLSX는 셀을 읽기 전에 행·열·셀 수·병합 영역·zip 크기 상한을 검사한다(§5 입력, 업로드 검사).
- 로컬 데모(`jettae demo run`)는 합성 자료가 아니라 공정위 의결서 표 전사 행(검증 전)의 값을 그대로 쓴다(§3).
- CI(`.github/workflows/ci.yml`)는 유료 호출 없이 백엔드 검사·폐기용 PostgreSQL·화면 검사·E2E를 실행한다(§8).
